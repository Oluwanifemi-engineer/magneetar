## 1. The verdict in one paragraph

Magneetar is a **legitimate, reviewable Play app** in the anti-theft category
(precedent: Cerberus, Prey, Avast Anti-Theft all ship on Play with device
admin + camera/mic + background location, declared honestly). The Play Protect
hard block you hit was a **sideload-channel problem, not a policy problem** —
Play-installed apps inherit a trust baseline and the permission declarations
give Google the legitimate-use context. The remaining work is operational
(assets, fresh AAB, forms, keystore rotation), not architectural. **Estimated
time to a submittable state: 1 working day of focused execution.**

### G4. Keystore security
The release keystore + `local.properties` (which holds passwords) are **only
on this machine**. Play can never restore a lost keystore — losing it means a
forced app repackage or permanent upload loss. **Action:** back both up to a
password manager/vault AND rotate the fallback keystore password (the
checklist notes the current fallback `magneetar123` must go).

## 4. Things that look like gaps but are NOT blockers

- **`BIND_DEVICE_ADMIN` in the play build** — keep it, declare it via the
  Permissions Declaration (Cerberus-class precedent). Fallback if rejected:
  remove `wipe-data` from `device_admin.xml` (one line).
- **SMS relay absent from play flavor** — correct by design; it stays
  sideload-only. The play build keeps network/FCM commands + the offline
  queue.
- **Live alert-delivery gaps (Twilio 401, no email sender)** — these affect
  *runtime alerting*, not Play review. Still fix them before launch: an
  anti-theft app whose SMS/WhatsApp/email alerts fail is a real product
  problem (see `docs/PROJECT_STATUS.md` alert-channel table).

## 5. What happens at review

Anti-theft apps with device admin + background location get a **manual
review** pass. Expect Google to ask about:
1. Why background location (theft detection when the app is closed) —
   answered by the prominent disclosure + FGS service type.
2. Why device admin (thief-resistant uninstall, remote lock/wipe) —
   user-consented at activation.
3. Evidence capture (camera/mic only during an armed theft response).
Keep this verdict + `docs/security.md` + `docs/play-store-checklist.md` ready
to paste into any review-question responses.

## 7. Verification tooling added this session

- `scripts/verify-sim-swap-live.py` — one-shot **live SIM-swap probe**:
  registers a throwaway device through the public API, fires a
  `sim_changed=true` ping, polls the server DB for the always-deliver alert
  rows, then self-cleans **every** row it creates (including audit_log).
  Exit codes: 0 = delivered, 1 = didn't fire, 2 = couldn't verify,
  3 = fired but some channels failed. **Live-proven**: push delivered=1;
  email/WhatsApp/SMS fail only because the Twilio account is suspended.
- `scripts/alert-smoke-test.py` — already existed; sends one real WhatsApp +
  SMS and verifies delivery (use after recharging Twilio).
- `scripts/twilio-config-check.py` — already existed; validates creds + lists
  SMS-capable numbers.

Run order after Twilio is recharged:
